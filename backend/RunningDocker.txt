------- Notes on building locally vs cloud ---------

The way we compose will be done the same way on AWS. That is, compose builds first an image
from the Dockerfile (which tests then runs the backend). Then we build a specific nginx
image too, with the config file passed to it. Running this through compose allows for
the reverse proxy set up we need.

Importantly, we will still need to build a seperate server image alone! This is what gets
saved to docker hub that AWS automatically pulls from during build. AWS does:
- build server image from hub (instead of docker file)
- then builds nginx (from the conf file we paste into 'user data')
- compose runs these (compose file pasted too)

This should allow correct rate-limiting that we've set up.

We compose locally for development, to ensure all works as intended.
